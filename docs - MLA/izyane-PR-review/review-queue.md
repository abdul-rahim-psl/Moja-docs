| - | ---- | ------------------- | ------------------ |
| 1 | `cch-rule-016` | Flags a creditor account that has received an unusually high number of separate transactions within a single day (fan-in / mule-account signal). | Correct rebind and parameter wiring; exits `.x00` unconditionally pending corridor support (expected, honestly documented). | 2 | `cch-rule-018` | Flags an outgoing payment significantly larger than the debtor's own 90-day same-currency maximum. | Strong fix: correctly implements the FSD's required `.x00`/`.x01` split (no history at all vs. no same-currency history) with a test purpose-built to catch a wrong-maximum regression. | 3 | `cch-rule-020` | Flags an incoming payment significantly larger than the creditor's historical average amount (z-score based). | **Most severe finding in the queue so far.** The z-score function's self-reference check can never succeed once bound to pacs.008 — it will silently return "insufficient data" on every real transaction once its masking guard is later lifted, unless fixed in the same pass. |
| 4 | `cch-rule-024` | Flags a creditor whose one outgoing payment matches the sum of several recent incoming payments, nothing retained (pass-through/mule pattern). | Clean, correctly verified rebind; avoids rule-020's self-reference trap by construction. | 5 | `cch-rule-026` | Same pass-through pattern as rule 024, but where a commission percentage is retained before funds move on. | Correct rebind, inherits rule-024's safe query shape. | 6 | `cch-rule-030` | Flags a debtor paying a creditor they have little or no prior payment history with (1st / 2nd / 3rd+ payment). | **Genuine bug fix, verified against the Dev Guide's band table:** pre-PR, the rule threw an error on a debtor's first-ever payment instead of scoring it — meaning it could never fire its own primary, highest-severity signal. | 7 | `cch-rule-044` | Counts a debtor's lifetime number of successful outgoing transactions (trust/experience signal; low count = suspicious). | Same defect class and fix as rule-030 (threw on a zero count instead of banding it), independently re-verified against the Dev Guide.
